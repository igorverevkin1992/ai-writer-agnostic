# КОНВЕЙЕР · Запуск

Руководство автора: от пустой папки до принятой главы. Всё общение с конвейером — по-русски: команды,
справка, панель. У каждой команды есть латинский синоним (`konveyer export` = `konveyer экспорт`).

## 1. Установка

```
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[llm,dev]"                            # без SDK моделей: pip install -e .
konveyer доктор
```

Требуется Python 3.11+. Ключи моделей — в `.env` рабочей области (`GEMINI_API_KEY`, `ANTHROPIC_API_KEY`);
без ключей любая роль работает в ручном режиме: конвейер сохраняет промпт, вы вставляете ответ.

## 2. Новый проект серии

```
konveyer проект создать ~/Серия --имя "Гаражи" --томов 2
```

Мастер спрашивает название, число томов, единицу объёма и набор модулей, создаёт раскладку
(`Библиотека/`, `главы/`, `выгрузки/`, `журналы/`, `сырьё/`, `драматургия/`), манифест `проект.yaml`,
стартовый комплект документов с пометками `⚠ заполнить` и git-репозиторий библиотеки.
Первое решение (Р-001: модели и параметры ролей) записывается в журнал решений автоматически.

`--профиль угар` — создать проект по профилю эталонной серии (переопределения типов и плагин-парсеры).
`--да` — без вопросов, все умолчания.

## 3. Онбординг существующих материалов

```
konveyer импорт ~/Материалы/*.docx ~/Материалы/заметки.md
konveyer онбординг                       # предложение «файл → тип» с предпросмотром разбора
konveyer онбординг --модель              # модельный слой (роль «архивариус»); по умолчанию — из конфига (onboarding_model_layer), --без-модели выключает
konveyer онбординг --решение <файл>=<принять|тип:<имя>|сырьё|отклонить|разбить|склеить:<файл>|колонка:<поле>=<заголовок>>
konveyer онбординг --модель --ответ <файл>=<путь>   # ответ архивариуса вручную (промпт — в онбординг/промпты/)
konveyer онбординг -р досье.md=тип:персонажи -р старое.txt=отклонить --применить
```

Импорт складывает копии в `сырьё/` и извлекает текст (docx, pdf, xlsx, csv, json, yaml, txt) в Markdown.
Онбординг классифицирует файлы по сигнатурам каталога типов, показывает, что именно машина прочитает
из каждого, задаёт вопросы по неоднозначностям и с `--применить` нормализует документы в библиотеку,
обновляет манифест и делает коммит. Ничего не переписывается молча: конфликты кладутся рядом
с пометкой, отчёт — в `журналы/онбординг.md`.

## 4. Готовность к первому такту

```
konveyer доктор        # установка, ключи, пины моделей, готовность проекта (что из обязательного не заполнено)
konveyer экспорт       # выгрузки из библиотеки; ошибки разметки — с файлом и строкой
konveyer линтер        # противоречия канона (машинный слой); --llm — модельный
konveyer типы          # каталог типов документов и модулей проекта
```

Обязательные для такта типы: стиль, повествование, план глав, персонажи, журнал решений
(плюс документы включённых модулей). Пока их нет — такт не запускается, а доктор говорит, чего не хватает.

## 5. Такт главы

```
konveyer такт 5                # весь такт с паузами на шагах автора
```

или пошагово: `собрать 5` → `написать 5` → `проверить1 5` → `проверить2 5` → `приёмка 5` →
правки в `главы/05/правки.md` → `правки-внести 5` → `дифф-контроль 5` → `принять 5` → `канон 5`.

- Э1 (формальные проверки) считает метрики только по нормам документа стиля; `konveyer нормы --калибровать`
  предлагает коридоры по вашим образцам, `--утвердить` записывает их в канон.
- Э2 (смысловые проверки) читает чек-листы включённых модулей; флаги приходят в `приёмка.md` и `приёмка.html`.
- `konveyer решение 5 F-003 отклонить --причина "..."` — решение по любому флагу без правки JSON.
- Канонист готовит записи в канон; в библиотеку они попадают только после вашей подписи.

## 6. Панель

```
konveyer панель          # или Запустить_панель.command / Запустить_панель.bat
```

Панель работает только на 127.0.0.1 и повторяет всё, что умеет командная строка: проект, онбординг,
очередь глав, чтение с флагами, правки, решения, дифф, приёмка, драматургия, журналы, регрессия.

## 7. Тома, регрессия, бэкап, учёт

- `konveyer том статус`, `konveyer том закрыть 1`, `konveyer том открыть 2` — жизненный цикл тома.
- `konveyer золотой ...` и `konveyer регрессия` — золотые тесты из пойманных ошибок.
- `konveyer пере-тест` — пакет пере-теста моделей; `--зафиксировать` пишет пины в `журналы/пины.json`,
  смена модели без пере-теста даёт предупреждение при генерации.
- `konveyer бэкап --push` / `--архив` — копии; `konveyer учёт` — деньги и время по главам, прогноз тома.
- Деньги и время настраиваются в `конфиг.yaml` (образец — `konveyer/data/конфиг.пример.yaml`, копируется в новый
  проект): цены каждой роли `цена_вход_1м`/`цена_выход_1м` за 1 млн токенов (без них `учёт` не считает ориентиры),
  `пороги: {стоимость_главы, расход_за_сутки}` — предупреждения по деньгам (FR-EC-2), `пауза_автора_мин` — пауза,
  после которой время автора не считается временем задачи (FR-CT-2), `лимит_окна` — мягкий лимит окна Писателя,
  `текущий_том` — том, над которым идёт работа.
- `konveyer проект индекс` — пересобрать индекс библиотеки из манифеста после правки `проект.yaml` руками
  (индекс генерируется системой и правится только через манифест, FR-DM-3); `доктор` напоминает, если он отстал.

## 8. Обновления и тесты

```
ruff check konveyer tests
PYTHONUTF8=1 python -m pytest tests/ -q
```

Миграционные тесты профиля эталона выполняются, если задана `KONVEYER_ETALON=/путь/к/библиотеке`.
Сборка панели: `cd panel && npm ci && npm run build` (результат — `konveyer/data/панель`, коммитится).
