# КОНВЕЙЕР · Запуск

Руководство автора: от пустой папки до принятой главы. Всё общение с конвейером — по-русски: команды,
справка, панель. У каждой команды есть латинский синоним (`konveyer export` = `konveyer экспорт`);
`konveyer --help` показывает команды по разделам, `konveyer <команда> --help` — её флаги.

## 1. Установка

Нужен Python 3.11 или новее (python.org; на Windows отметьте «Add python.exe to PATH»). Виртуальное
окружение не обязательно — установка одной командой из папки с кодом конвейера:

```
pip install -e ".[llm,onboarding]"     # SDK моделей + разбор .docx/.xlsx/.pdf при импорте
pip install -e .                       # минимум: без SDK (ручной режим) и без тяжёлых разборщиков
konveyer доктор
```

Ярлыки панели `Запустить_панель.bat` (Windows) и `Запустить_панель.command` (macOS, двойной клик; Linux —
`./Запустить_панель.command`) при первом запуске сами создают окружение `.venv`, ставят конвейер и
открывают панель — терминал для них не нужен.

Необязательные части ставятся отдельно и без них конвейер говорит, чего не хватает, а не падает:
`konveyer[llm]` — SDK Gemini и Anthropic; `konveyer[docx]`, `konveyer[xlsx]`, `konveyer[pdf]` — импорт
этих форматов и сборка рукописи тома в .docx (`konveyer[onboarding]` — все три сразу).

Ключи моделей — в файле `.env` рабочей области (`GEMINI_API_KEY` или `GOOGLE_API_KEY` для Писателя,
`ANTHROPIC_API_KEY` для остальных ролей); образец — `.env.example`. Без ключей конвейер работает в ручном
режиме — см. раздел 9.

## 2. Новый проект серии

```
konveyer проект создать ~/Серия --имя "Гаражи" --томов 2
```

Мастер спрашивает папку, название, число томов, набор модулей, методику драматургии и профиль серии
(любой ответ можно задать флагом: `--модули`, `--методика`, `--профиль`; `--да` — без вопросов, все
умолчания). Создаётся раскладка (`Библиотека/`, `главы/`, `выгрузки/`, `журналы/`, `сырьё/`,
`драматургия/`, `промпты/`…), манифест `проект.yaml`, стартовый комплект документов с пометками
`⚠ заполнить` и git-репозиторий библиотеки. Первое решение (Р-001: модели и параметры ролей) записывается
в журнал решений автоматически.

- Есть свои материалы (сценарий А)? Создавайте проект с `--без-комплекта`: иначе после онбординга рядом
  с вашим документом стиля или планом глав останется незаполненный каркас того же типа, и `доктор`
  будет требовать его заполнить или удалить.
- `--профиль угар` — проект по профилю эталонной серии (переопределения типов и плагин-парсеры);
  свой профиль — раздел 11.
- `--без-git` — библиотека без репозитория (не рекомендуется: без git нет отката и второй копии).

## 3. Онбординг существующих материалов

```
konveyer импорт ~/Материалы                              # папка, файл или .zip; можно несколько путей
konveyer импорт ~/Материалы/стиль.docx ~/Материалы/заметки.md
konveyer онбординг                                       # предложение «файл → тип» с предпросмотром разбора
konveyer онбординг --модель                              # + модельный слой (роль «архивариус») для неуверенных файлов
konveyer онбординг -р досье.md=тип:персонажи -р старое.txt=отклонить
konveyer онбординг --применить                           # нормализация в библиотеку, манифест, коммит
```

Импорт складывает копии в `сырьё/` и извлекает текст в Markdown; поддерживаются `.md`, `.txt`, `.docx`,
`.rtf`, `.pdf`, `.csv`, `.tsv`, `.xlsx`, `.html`, `.json`, `.yaml`. Файлы без извлечения остаются в
`сырьё/оригиналы` с причиной — конвертируйте их в `.md`/`.docx` и повторите импорт (импорт идемпотентен:
уже импортированные файлы не дублируются).

Онбординг классифицирует файлы по сигнатурам каталога типов, показывает, что именно машина прочитает
из каждого (`онбординг/предложение.md`), задаёт вопросы по неоднозначностям и с `--применить`
нормализует документы в библиотеку, обновляет манифест и делает коммит (`--без-коммита` — только записать).
Решения автора: `файл=принять`, `тип:<имя>`, `сырьё` (оставить как справочный материал), `отклонить`.
Ничего не переписывается молча: конфликты повторного импорта кладутся рядом с пометкой; отчёт готовности
(что распознано, что в сырьё, чего не хватает) — `онбординг/отчёт.md`.

## 4. Готовность к первому такту

```
konveyer доктор        # установка, ключи, пины моделей, сохранность, готовность проекта
konveyer экспорт       # выгрузки из библиотеки; ошибки разметки — с файлом и строкой
konveyer линтер        # противоречия канона (машинный слой); --llm — модельный
konveyer типы          # каталог типов документов и модулей проекта
```

Минимальный комплект для первого такта: (а) документ стиля с нормой хотя бы по объёму главы,
(б) план глав с хотя бы одной записью (номер, что происходит), (в) документ мира или персонажей,
если план называет имена. Всё остальное необязательно: без документа секция окна просто не появляется.
Документы включённых модулей `доктор` тоже называет поимённо, пока их нет. Пока комплект неполон,
такт не запускается, а `доктор` говорит, чего не хватает.

## 5. Такт главы

```
konveyer такт 5                # весь такт с паузами на шагах автора
```

или пошагово: `собрать 5` → `написать 5` → `проверить1 5` → `проверить2 5` → `приёмка 5` →
правки в `главы/005/правки.md` → `правки-внести 5` → `дифф-контроль 5` → `принять 5` → `канон 5`.
Папка главы — `главы/005/` (три цифры номера); внутри — `окно.md`, черновики `черновик_k.md`,
`флаги.json`, `приёмка.md`, `правки.md`, `решения.json`, `пакет_канона.md` и промпты ручного режима.

- Э1 (формальные проверки) считает метрики только по нормам документа стиля; `konveyer нормы --калибровать`
  предлагает коридоры по вашим образцам, `--утвердить` записывает их в канон.
- Э2 (смысловые проверки) читает чек-листы включённых модулей; флаги приходят в `приёмка.md` и `приёмка.html`.
- `konveyer решение 5 F-003 отклонить --причина "..."` — решение по любому флагу без правки JSON.
- `konveyer статус 5` — карточка главы и следующий шаг; `konveyer откат 5` — на шаг назад
  (принятая глава откатывается через revert коммита приёмки с пересчётом выгрузок).
- Канонист готовит записи в канон (`пакет_канона.md`); в библиотеку они попадают только после вашей
  подписи (`konveyer канон 5 --apply`).

## 6. Панель

```
konveyer панель          # или Запустить_панель.command / Запустить_панель.bat
```

Панель работает только на 127.0.0.1 и ведёт весь такт и онбординг: проект, онбординг, очередь глав,
чтение с флагами, правки, решения, дифф, приёмка, драматургия, канон, журналы, регрессия, пере-тест,
бэкап, тома. Только из терминала: `начать`, `проект создать`, `типы`, `проверка` (Э1 по произвольному
файлу), `нормы --калибровать`, `метрики`, `золотой`, `журнал`, `статус`, `найти`, `правки` (предпросмотр),
`дифф`, `дашборд`, `библиотека-отделить`.

## 7. Тома, регрессия, пере-тест, учёт

- `konveyer том статус`, `konveyer том закрыть 1`, `konveyer том открыть 2` — жизненный цикл тома:
  закрытие делает снапшот в библиотеку, тег `том-N`, рукопись `рукопись/ТомN.md` (+ `.docx` при
  установленном `konveyer[docx]`) и статистику.
- `konveyer золотой <id> <фрагмент.md> --expect V1.3_был` и `konveyer регрессия` — золотые тесты из
  пойманных ошибок; пустой корпус регрессию зелёной не делает.
- `konveyer пере-тест` — пакет пере-теста моделей; `--зафиксировать` пишет пины в `журналы/пины.json`
  (только при зелёной регрессии), смена модели без пере-теста даёт предупреждение при генерации.
- `konveyer учёт` — деньги и время по главам и ролям, прогноз остатка тома; `konveyer журнал` — последние
  вызовы моделей.

## 8. Сохранность и восстановление

```
konveyer бэкап                                   # состояние копий, возраст архива
konveyer бэкап --добавить-remote диск /Volumes/Диск/Серия.git   # папка на внешнем диске (создаётся как bare-репозиторий)
konveyer бэкап --добавить-remote github git@github.com:…       # или удалённый git
konveyer бэкап --push                            # библиотека — во все места хранения
konveyer бэкап --архив                           # zip рабочей области (по умолчанию ../архивы)
```

Библиотека должна лежать минимум в двух местах — `доктор` предупреждает, пока их меньше. Архив рабочей
области (главы, журналы, драматургия, снапшоты, рукопись, регрессия, онбординг, `конфиг.yaml`,
`проект.yaml`) делается по команде и автоматически после каждой приёмки, если в `конфиг.yaml` задан
`backup_dir` (`backup_keep` — сколько архивов хранить). Библиотека в архив не входит: она в git.

**Восстановление** на новой машине или после потери папки:

1. Установите конвейер (раздел 1) и создайте пустую папку проекта.
2. Распакуйте последний `рабочая_область_<дата>.zip` в неё (появятся `конфиг.yaml`, `проект.yaml`,
   `главы/`, `журналы/`…).
3. Верните библиотеку из любого места хранения: `git clone <папка-на-диске или url> Библиотека`
   (путь должен совпадать с `library_dir` в `конфиг.yaml`).
4. `konveyer экспорт` — выгрузки пересобираются из библиотеки; `konveyer доктор` — проверка, что всё на
   месте, затем `konveyer статус` покажет, на каком шаге остановилась каждая глава.

Текущий и прошлые тексты глав в библиотеке — история git: `git -C Библиотека log`, теги `глава-N` и `том-N`.

## 9. Ручной режим (без ключей или при отказе API)

Каждая модельная роль умеет работать без модели: конвейер печатает готовый промпт в файл, вы прогоняете
его в любом чате и возвращаете ответ файлом или вставкой в панели (вид главы, кнопки «Вставить ответ»).

| Роль | Где промпт | Как вернуть ответ |
|---|---|---|
| Писатель | `главы/005/окно.md` | сохранить текст как `главы/005/черновик_{k+1}.md`, затем `konveyer написать 5 --manual` |
| Верификатор-2 (Э2) | `главы/005/промпт_э2.md` (повторно после правок — `промпт_э2_повторно.md`, вкус — `промпт_вкуса.md`) | JSON в `флаги.json`, затем `konveyer проверить2 5 --manual` (`--повторно --manual`; вкус — `вкус.json`) |
| Внесение правок | `главы/005/промпт_правок.md` (дословные БЫЛО/СТАЛО вносятся кодом, промпт нужен только для свободных указаний) | исправленный текст как `черновик_{k+1}.md`, затем `konveyer правки-внести 5 --manual` |
| Канонист | `главы/005/промпт_канониста.md` | без модели пакет собирается из ваших решений по самоволкам; допишите `пакет_канона.md` руками и примените `konveyer канон 5 --apply` |
| Аналитик драматургии | `драматургия/промпты/<уровень>.md` | вставка ответа в панели (вид «Драматургия») |
| Линтер (модельный слой) | `журналы/линтер_промпты/<документ>.md` | ответ не принимается автоматически — правьте канон по найденному сами |
| Архивариус (онбординг `--модель`) | промпт не сохраняется | без модели работает машинная классификация; решения задаются `-р файл=тип:…` |

Регрессия золотых тестов Э2 без ключей пропускается с пометкой (Э1 выполняется всегда).

## 10. Обновление

```
git pull                                   # или распакуйте новую версию кода поверх старой
pip install -e ".[llm,onboarding]"         # зависимости; точные проверенные версии — requirements.lock
konveyer доктор                            # установка, ключи, пины
konveyer экспорт && konveyer регрессия     # выгрузки пересобираются, золотые тесты по-прежнему зелёные
```

Проект автора при обновлении не ломается: манифест и выгрузки мигрируются автоматически с резервной
копией (`проект.v<N>.<дата>.yaml` рядом). После обновления SDK или смены модели — `konveyer пере-тест`,
а фиксация новых пинов требует зелёной регрессии. Установка ровно проверенного набора версий:
`pip install -r requirements.lock && pip install -e . --no-deps`.

## 11. Настройка под свою серию: профили, типы, парсеры, язык, промпты

Всё серийное живёт в проекте, а не в коде; движок можно обновлять, не теряя настроек.

- **Переопределение типа документа.** Положите `типы/<тип>.yaml` в папку проекта — он дополняет
  каталог движка (колонки и их синонимы, секции, что идёт в окно, сигнатуры классификации). Что читает
  каждый тип — `konveyer типы` и `docs/Соглашения_типов.md`. Чаще всего достаточно не переопределять
  тип, а сопоставить имена колонок в `проект.yaml` (блок «библиотека»).
- **Плагин-парсер** для экзотического формата: модуль `типы/парсеры/<имя>.py` в проекте и в YAML типа
  строка извлечения `{вид: плагин, функция: "<имя>:<функция>"}`; функция получает путь к документу и
  возвращает записи выгрузки. Пример — профиль `konveyer/data/профили/угар`.
- **Профиль серии** — папка с любыми из подпапок `типы/`, `модули/`, `методики/`, `линтер/`, `промпты/`,
  `шаблоны/`; `konveyer проект создать --профиль <имя или путь>` копирует её в новый проект.
- **Языковой слой.** Сокращения, лексемы и усилители для метрик — `языки/ru.yaml` движка; проектный
  `языки/ru.yaml` дополняет списки, `сокращения.txt` — свои сокращения для сплиттера фраз.
- **Промпты ролей.** Файлы в `промпты/` проекта переопределяют шаблоны движка: `верификатор2_система.md`,
  `верификатор2_вкус_система.md`, `канонист.md`, `линтер.md`, `архивариус.md`, `правки.md.j2`; шаблон
  окна Писателя — `шаблоны/окно.md.j2`. Все они входят в отпечаток регрессии: изменили — прогоните
  `konveyer регрессия`.
- **Методики драматургии** — плагины в `методики/<имя>/` (круг Хармона, трёхактная, сцена-сиквел,
  арки, пустая); своя методика — та же папка в проекте.

## 12. Тесты (для разработчика)

```
ruff check konveyer tests
PYTHONUTF8=1 python -m pytest tests/ -q
KONVEYER_ETALON=/путь/к/ugar-library PYTHONUTF8=1 python -m pytest tests/профиль_угар -q
```

Тесты профиля эталона выполняются, когда задана `KONVEYER_ETALON` (в CI библиотека эталона клонируется
и проверяется в каждом прогоне); без переменной они пропускаются с пометкой, заданный неверный путь —
ошибка. Сборка панели: `cd panel && npm ci && npm run build` (результат — `konveyer/data/панель`, коммитится).
