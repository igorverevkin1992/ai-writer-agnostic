# ai-writer-agnostic

Агент для сценариев вертикальных микросериалов. Жанры — пакеты данных в `packages/kb/genres/`:
женский психологический триллер мести и женское ромэнтэзи с реваншем и наказанием подлеца. Полное ТЗ — [SPEC.md](SPEC.md), правила для Claude Code — [CLAUDE.md](CLAUDE.md).

## Как запустить

Нужно: Node.js 22.12 или новее и pnpm 10.

```bash
pnpm install
cp .env.example .env   # вписать ключи API
pnpm dev               # откроет приложение в браузере: http://localhost:5173
```

Без ключей: `pnpm demo` — то же приложение, но модели отвечают заготовками по эталону
«Муж женился на мне ради крови». Можно пройти весь путь от идеи до экспорта и посмотреть
все экраны. Демо хранит проекты отдельно (`data/demo.db`) и ничего не тратит.

## Экраны

- **Сейчас** — одна задача и критерий готовности одной строкой, не больше трёх замечаний.
- **Библия**, **Сезон** (таблица 60 серий, опорные точки, кривая страдания и кайфа),
  **Серия** (карточка, сценарий, доработка фрагмента — 5 вариантов на выбор),
  **Проверки** (все замечания), **Экспорт**, **Расходы**.

Экспорт: Word (логлайн, библия, таблица сезона, сценарии), Excel (сезон, карточки,
замечания, промпты для видео), промпты для ИИ-видео (внешность героев — только из библии),
Markdown, JSON.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm dev` | Запускает сервер (порт 3001) и интерфейс (порт 5173) |
| `pnpm demo` | То же без ключей: модели отвечают заготовками по эталону |
| `pnpm test` | Тесты. Реальные модели не вызываются |
| `pnpm lint` | Линтер и проверка типов |
| `pnpm kb:check` | Проверяет базу знаний `packages/kb` и показывает ошибки |
| `pnpm seed-holes` | Вносит 30–50 ошибок в эталонный план и показывает, сколько из них находит код |
| `pnpm pilot` | Пилот: карточки и сценарии первых 15 серий эталона, чек-лист, метрики, «можно ли снимать». Реальные вызовы, лимит `--budget=40` ($) |
| `pnpm smoke` | По одному реальному вызову на каждую роль: проверяет ключи и названия моделей. Стоит несколько центов |
| `pnpm eval` | Оценка аудитора на эталоне и посеянных дырах, отчёт в `reports/`. Реальные вызовы, лимит `--budget=25` ($). `--architect=heavy` — сравнение с Fable |

## Модели и расходы

- Какая модель играет какую роль — в `config/models.yaml`. Сменить модель — одна строка там.
- Каждый вызов модели записывается в базу (`data/app.db`, таблица `llm_calls`): роль, модель, токены, стоимость, время.
- Лимит бюджета проекта — `budget.project_limit_usd` в `config/models.yaml`. На 80% — предупреждение, на 100% — остановка.
- Проверяющая модель всегда из другого семейства, чем автор текста. Иначе проверка не запускается.
- Если Claude или Gemini недоступны, работу подхватывает резервный поставщик из `.env` (`RESERVE_*`).

## Как работает агент

Идея → три концепции (продюсер выбирает одну) → логлайн → библия → план сезона.
После библии и плана код проверяет всё, что можно посчитать, а затем «адвокат дьявола»
другого семейства ищет дыры по 11 типам. Автор отвечает только ссылкой на факт или новым
фактом, судья решает, закрыта ли дыра. Шаг нельзя утвердить, пока открыты блокирующие замечания.

Дальше: карточки серий (архитектор, блоками по 10, утверждение тоже блоками) → сценарии
(Gemini по карточке, сжатой библии и двум предыдущим сериям; Claude проверяет шестью
контролёрами, код — метриками) → доработка (продюсер выделяет фрагмент, писатель даёт
5 вариантов, выбор продюсера пишется в журнал творческого вклада).

Шаги агента идут в фоне: экран «Сейчас» сам обновляется, пока агент работает, и показывает ошибку,
если запуск сорвался. Если приложение закрыли посреди шага, при следующем запуске шаг помечается
как прерванный — его нужно запустить ещё раз.

API: `POST /api/projects`, `GET /api/projects/:id`, `POST /api/projects/:id/steps/:step/run|approve|skip`
(`run` отвечает сразу, ход работы — в `overview.job`; `{"wait": true}` — дождаться результата),
`GET /api/projects/:id/findings?status=open&limit=3`, `POST /api/findings/:id/resolve|dismiss`,
`GET /api/projects/:id/cards`, `GET /api/projects/:id/scripts/:ep`, `POST /api/projects/:id/polish`,
`POST /api/projects/:id/polish/choose`, `GET /api/projects/:id/overview`, `GET /api/projects/:id/export?format=docx|xlsx|json|md|video`,
`GET /api/projects/:id/costs`.

## Эталоны

В `fixtures/golden/` лежат эталонные проекты — по одному на жанр: «Муж женился на мне ради крови»
(триллер мести) и «Наследница Вороновых» (ромэнтэзи). На них работают демо-режим, `pnpm eval`,
`pnpm pilot` и посев дыр. Для ромэнтэзи добавляйте `--project=naslednitsa --genre=romantasy_revenge`.

## Разные сериалы

Продукт подходит для любых сериалов. Жанр, число серий, опорные точки, правила и чек-лист
берутся из жанрового пакета в `packages/kb/genres/`, а не из кода. Подробнее —
[packages/kb/README.md](packages/kb/README.md).

## Куда класть материалы

- `docs/` — правила жанра, чек-лист, методики, каталог дыр (Markdown).
- `legacy/` — код прототипа на React, если он есть.
- `data/` — проекты продюсера, в git не попадают.
