# КОНВЕЙЕР · карта проекта

Универсальный производственный конвейер книжной серии (ТЗ «Универсальный конвейер книжной серии» v1.0).
Пакет `konveyer`, Python 3.11+, CLI на typer, панель на React/Vite (собранная — в `konveyer/data/панель`).

## Принципы, которые проверяют тесты

- **П-1, ноль констант серии.** В коде движка нет имён персонажей, глав, тайн и названий серии;
  `tests/test_статика_п1.py` сканирует пакет. Всё серийное живёт в проекте (`проект.yaml`, библиотека) или в профиле.
- **П-3, одна точка записи в канон.** Библиотеку меняет только `canonchange.canon_change`
  (`tests/test_stage5_static.py`). Остальной код читает.
- **П-5, деградация.** Нет документа модуля — секции окна нет (без заглушек и предупреждений), а не падение; нет ключей — ручной режим.
- **П-6, детерминизм.** Экспорт и окно одинаковы при одинаковой библиотеке; кэш линтера — по отпечатку.
- **Русский интерфейс.** Команды, справка, панель, документы — по-русски; латинские имена — скрытые синонимы.

## Где что лежит

| Папка / файл | Что это |
|---|---|
| `konveyer/типы/*.yaml` | Каталог типов документов: извлечения, форматы, что в окно, коды линтера, сигнатуры классификации |
| `konveyer/модули/*.yaml` | Реестр модулей: какие типы требует, секции окна, чек-листы Э2, коды линтера |
| `konveyer/методики/` | Методики драматургии (плагины): круг Хармона, трёхактная, сцена-сиквел, арки, пустая |
| `konveyer/языки/ru.yaml` | Языковой слой: сокращения, лексемы, усилители (проект может переопределить) |
| `konveyer/шаблоны/` | Промпты ролей и шаблон окна `окно.md.j2` |
| `konveyer/data/демо/` | Демо-проект «Гаражи» (два тома); `data/профили/угар/` — профиль эталонной серии |
| `konveyer/catalog.py`, `manifest.py`, `declparse.py` | Каталог типов, манифест проекта, декларативный разбор (таблицы, секции, плагины) |
| `konveyer/exporter.py` | Экспорт библиотеки в `выгрузки/*.json` по манифесту, накопление известных имён |
| `konveyer/compiler.py`, `writer.py` | Окно главы по модулям, фильтр знания фокала; Писатель |
| `konveyer/metrics.py`, `verifier1.py`, `calibrate.py` | Реестр метрик Э1, проверки по нормам стиля, калибровка |
| `konveyer/verifier2.py`, `review.py`, `canonist.py` | Э2 по чек-листам модулей, приёмка, Канонист |
| `konveyer/lint.py` | Линтер канона по кодам модулей, кэш по отпечатку |
| `konveyer/onboarding/` | Импорт, извлечение, классификация, предложение, нормализация, применение, отчёт |
| `konveyer/project.py`, `pins.py`, `accounting.py` | Создание проекта и готовность, пины моделей, учёт денег и времени |
| `konveyer/steps/` | Сценарии команд (общие для CLI и панели) |
| `konveyer/cli.py`, `server.py`, `panel/` | Командная строка, HTTP-панель, исходники панели |
| `docs/` | Сгенерированные «Соглашения типов» и «Реестр метрик» (`konveyer типы --документация`) |

## Как работать с кодом

- Тесты: `PYTHONUTF8=1 python -m pytest tests/ -q`; линт: `ruff check konveyer tests`. CI гоняет оба на трёх ОС.
- Новый тип документа — YAML в `konveyer/типы/`, без кода; нестандартный формат — плагин `вид: плагин`
  в `типы/парсеры/` проекта. Новая метрика — регистрация в `metrics.py` (id нормы = id в документе стиля).
- Новая проверка линтера — код объявляется в `модули/*.yaml`, реализация в `lint.py`; тест
  `tests/test_этап5.py` проверяет, что чистый демо-канон даёт ноль находок.
- Любая запись в библиотеку — через `canonchange.canon_change`; любое серийное имя — в данные, не в код.
- Панель: `cd panel && npm ci && npm run build` (Node 22), собранное коммитится вместе с изменением.
- Миграционные тесты эталона: `KONVEYER_ETALON=/путь/к/библиотеке pytest tests/профиль_угар`.
