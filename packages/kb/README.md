# База знаний

Все правила жанра, методики и ограничения живут здесь как данные. Код и промпты их только читают.

## Жанровые пакеты: один продукт — много сериалов

Каждый проект (сериал) выбирает жанровый пакет из `genres/`. Пакет говорит, какие файлы
действуют для этого жанра и формата: правила, каркас сезона (число серий, бесплатные серии,
опорные точки, лестница злодеев или ствол с матрёшкой), чек-лист, персоны зрителей, правовые и
производственные рамки, жанровые подсказки.

- **Новый сериал в том же жанре** — просто новый проект. Ничего добавлять не нужно.
- **Новый жанр или формат** (например, 30 серий без злодеев) — новый файл `genres/<id>.yaml`
  и свои `rules/`, `frames/`, `checklist/`. Код не меняется.
- **Несколько линий** (месть и любовь): в каркасе `lines` и `rhythm.max_without_line` — код следит,
  чтобы ни одна линия не пропадала надолго. Подсказки для моделей — в `guides/<id>.yaml`.
- **Термины героя** (`terms` в пакете: «героиня» или «герой», название раны) — умолчания жанра.
  Проект сможет задать свои; тексты правил пишут `{{hero.nom}}`, `{{hero.gen}}`, `{{hero.dat}}`
  или слово жанра по умолчанию, а модель читает его как термин проекта.
- Всё, что относится к конкретному сериалу (герои, мир, тайна), — данные проекта, не базы знаний.
  Эталонные концепты лежат в `fixtures/golden/`.

## Общие правила и переопределения

Четыре правила из методик (Моуэри, Рабкин, Уэйланд) действуют во всех жанрах и лежат один раз в
`rules/common.yaml` под номерами C01–C04: три ставки сезона, арка героя по Лжи и Правде, цена каждой
победы, обещание жанра в первой серии. Жанр подключает их строкой `common_rules: true` в
`genres/<id>.yaml`; в пакете они идут после жанровых правил R01…

Что у жанра своё — в его `rules/<id>.yaml`, раздел `common:`, по номеру правила: `text`, `severity`,
`fix_hints`, `check.code`, `check.llm`, `check.run` (список проверок заменяется целиком; `code: null`
или `llm: null` убирает эту часть, например когда опорную точку уже проверяет другое правило жанра).
Так триллер ведёт арку героини до перезагрузки №1 вместо мидпоинта и оставляет «обещание жанра»
судье, потому что опорную точку первой серии уже проверяет R14.

## Числа — из одного источника

Тексты правил, пунктов чек-листа, персон и подсказок не называют лимиты числом: они пишут
подстановку, а загрузчик при сборке пакета (`genreKit`) заполняет её из каркаса и рамок жанра.
Так один и тот же файл правил работает с другим барьером, другой длиной сезона или другими
производственными лимитами.

| Подстановка | Откуда | Пример |
|---|---|---|
| `{{L}}`, `{{free}}`, `{{tolerance}}`, `{{duration.min/max/target}}` | `frames/<id>.yaml` | `{{L}}` → 60 |
| `{{inputs.<имя>}}` | входы каркаса | `{{inputs.paywall}}` → 10 |
| `{{anchors.<id>}}`, `{{anchors.<id>.min}}`, `{{anchors.<id>.max}}` | опорные точки | `{{anchors.reset1}}` → 25–30 |
| `{{blocks.<n>}}`, `{{blocks.<n>.min/max}}` | блоки каркаса, с 1 | `{{blocks.3}}` → 10–12 |
| `{{rhythm.<ключ>}}` | ритм каркаса | `{{rhythm.max_same_hook_run}}` → 2 |
| `{{limits.<ключ>}}` | `constraints/<production>.yaml`, limits | `{{limits.max_speakers_per_scene}}` → 4 |
| `{{metrics.<ключ>}}` | там же, script_metrics | `{{metrics.max_line_words}}` → 15 |
| `{{hero.nom/gen/dat}}`, `{{wound}}` | `terms` жанра (или проекта) | `{{hero.gen}}` → героини |
| `{{age_rating}}` | `constraints/<legal>.yaml` | → 16+ |
| `{{L/30}}`, `{{0.42*L}}` | арифметика над числами выше, округляется | на 60 серий → 2 и 25 |

Подстановки работают и в параметрах проверок: `min: "{{L/30}}"` у правила о перезагрузках даёт
число, которое растёт с длиной сезона. Неизвестная подстановка — ошибка `pnpm kb:check` с именем
файла и правила. Словари хуков первых секунд (`hook_kinds`) и типов обрыва (`hook_types`) тоже лежат
в каркасе; гайды и методики называют их id в скобках.

Файлы с `stub: true` ждут материалов продюсера. Когда файл заполнен, `stub` убирают:
например, у чек-листа тогда сумма баллов обязана быть ровно `total`.

Проверить базу после правки: `pnpm kb:check` (или `pnpm --filter @aiw/kb check`). Ошибка покажет
файл, строку и поле; подстановки, переопределения и ссылки на опорные точки проверяются там же.
