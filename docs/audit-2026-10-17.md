# Аудит программы — 17 октября 2026

Цель: найти всё, что мешает получить максимально хороший результат, и выстроить порядок работ.
Повод: два реальных прогона оценки аудитора на «Купале» (57% дыр продюсера найдено при цели 70%)
и предстоящий прогон на «Приме» (vertical_thriller). Проверялись пять зон: поставщики моделей и
скрипты, конвейер и промпты, аудитор (код и модель), база знаний, приложение. Все ссылки — на
текущий main (коммит 5491b08). Lint и 331 тест зелёные.

## Главные выводы

1. Аудитор плана не видит библию. При проверке плана сезона модель получает только строки серий
   и 6–8 «фактов». Правила мира с числами, мотивы злодеев, даты, улики, ружья и таблица знаний
   ей не показываются (`checks/llm/devilAdvocate.ts:148-150`). Это объясняет большинство
   пропущенных дыр «Купалы»: нарушения числовых правил, злодей против своей выгоды, арифметика дат.
2. Строки серий слишком бедные. В них нет типа обрыва, режима знания, настроения, якорей,
   `acts_on` (`checks/llm/texts.ts`). Поэтому ни автор (при написании плана кусками), ни критик
   не могут проверять ритм, повторы обрывов, саспенс и знание персонажей по тексту.
3. Один проход на категорию по всем 60 сериям ограничивает не вход, а выход: модель выдаёт 10–15
   находок на категорию и останавливается. Нужны проходы по блокам плюс сквозной проход.
4. «Приме» подсовывают чужие правила. Каталог дыр, категории Ж («Лестница злодеев»), В, часть З,
   словарь и ряд принципов методик написаны под ревендж: «мидпоинт», «8-я серия», «три серии
   страдания», «12 слов», «ранг злодея». Для триллера это гарантированные ложные дыры.
5. Прогон по «Приме» сейчас почти ничего не измерит: списка дыр продюсера нет, посеянные дыры в
   31 случае из 35 ловит код, а не модель. Нужен эталон с намеренными смысловыми дырами.
6. Тип дыры у находок категории берётся первым из списка (`devilAdvocate.ts:94`), поэтому оценка
   на посеянных дырах не может засчитать модели целые типы (11 «знание», 7 «хронология»).
7. В приложении часть кодовых проверок не запускается: для карточек и сценариев не вызывается
   `runCodeChecks` (`pipeline/runners.ts:300-321, 388-396`), то есть биты, «золотые три»,
   линтер сценария (говорящие головы, планы, звук) работают только в eval/pilot.
8. Автор не видит правил критика: 179 правил категорий ревью, вопросы каталога дыр, `check.llm`
   и `fix_hints` правил жанра уходят только критику (`prompts/render.ts:50-110`).
9. План сезона пишется 8 кусками с потерей памяти и без согласования: куски по 3 серии,
   контекст предыдущих серий лишён типов обрывов и настроений, нет шага «исправь по находкам»,
   нет сохранения по частям (одна ошибка в пятом куске теряет оплаченные четыре).
10. Писатель теряет улики, ружья, ствол и матрёшку: сжатие библии уровня 1 включено всегда
    (`pipeline/compress.ts:122-136`, `runners.ts:359`), хотя вход в 10 раз меньше лимита.
11. Бюджет и устойчивость: лимит 50 долларов на проект нельзя поднять из приложения, шаг нельзя
    остановить, первый клик «Сценарии» запускает все 60 серий; один кривой или обрезанный ответ
    модели валит весь прогон; у Anthropic-потока нет таймаута; `--budget=25,5` даёт NaN и
    отключает защиту; резервная модель тарифицируется по самой дорогой цене.
12. Gemini: уровень размышлений не задан, мысли съедают лимит ответа и деньги.

## Подробные находки по зонам

### Аудитор (код и модель)
- План без библии (см. выше). Исправление: в проходах по плану давать `bibleText` плюс таблицы
  правил мира (`cost`/`cannot`), ружей (`planted_ep`/`fired_ep`), знания; цитаты из этого текста
  засчитывать, а не отбрасывать (`devilAdvocate.ts:88,112`).
- Ключ дедупликации «серия + цитата» склеивает разные дыры из одной строки и не склеивает одну
  дыру с разными цитатами (`devilAdvocate.ts:164-170`).
- Метрики оптимистичны: спорные сопоставления считаются найденными; судья сопоставления видит
  только строку находки, без текста плана; одна модель сопоставляет 220 находок с 68 дырами.
- Судья закрытия находок (`checks/llm/resolve.ts:227-243`) не видит план и закрывает дыру по
  одному объяснению автора; новый факт записывается в библию, план не меняется.
- Ложные срабатывания кода на «Купале»: 11 блокеров «якорь не отмечен» (разметка, не сюжет);
  «бьёт озноб» как насилие; `stakes.missing`/`promise.absent` цитируют событие целиком.
- Вопросы «кто был рядом» раздуты и покрывают только серии 1–5 (`texts.ts:419-429`, срез 30).
- Контролёры (`controllers.ts`) в eval не участвуют вовсе; их проверка цитаты строже `locateQuote`.
- Один обрезанный ответ (`OutputTruncatedError`) не повторяется и роняет `mapLimit` целиком.
- Категория Ж идёт на жанр без злодеев; каталог дыр не имеет типов «улика без окупаемости»,
  «правовая/медицинская достоверность», «злодей против выгоды».
- Посев дыр: 60% посевов — типы 7/11, которые код ловит тривиально; нет посевов смысловых дыр
  триллера (ружьё без выстрела, число правила против сцены, угроза без узнавания).

### Конвейер и промпты
- `runCodeChecks` не вызывается для карточек и сценариев в приложении (п. 7 выше).
- План сезона: куски 3–15 серий, контекст без полей ритма, нет reconciliation, нет partial save.
- Автор не получает правил критика (п. 8); схемы допускают произвольные `hook_type`/`hook_kind`
  (`schemas/season.ts:271`, `episodeCard.ts:336-340`), ошибка всплывает поздно как major.
- Писатель: сжатие уровня 1 всегда; у карточки нет поля «что заложить» (улики/ружья); нет
  плана-контура и следующего хука; память сценариев — два предыдущих текста без фактов.
- Факты извлекаются помощником только когда архитектор вернул ноль фактов (`runners.ts:239`).
- Переделка библии/плана/блока карточек идёт «с нуля», без открытых находок (только сценарии
  получают `fix_notes`).
- В триллер утекает ревендж-материал: каталог дыр, категория Ж, глоссарий-заглушка, поля схемы
  библии `villains`/`betrayal`/`secrets`, пустые «кейсы» при просьбе «сверься с кейсами».
- Тексты правил несут коды исследований «(L01 BLOCK)»; расхождения чисел: говорящих 3/4, слов
  12/15, «монолог» не определён.

### База знаний
- Ревендж-вопросы в общем каталоге дыр и в категориях Ж/В/З; методики противоречат жанру
  (Рабкин R06/R08, Уэйланд W9, Моуэри M31/M32 против V07/V09/reset1); V16 жёстко про барьер 10.
- Рейтинг 18+ в `constraints/ru_legal_thriller.yaml` против 16+ в концепте «Примы».
- Эталон «Прима» не измеряет полноту аудитора; при этом demo.yaml описывает реальную дыру
  (шаль Лики, серия 15), значит «без дыр» неверно.
- R08/R21/R24 без `check.llm`: код проверяет лишь галочки автора; R12 выполняется «по умолчанию».
- Общие правила R22–R25 продублированы в четырёх файлах под разными номерами.
- Жёсткие «60 серий / барьер 10» в гайде и персонах при параметрическом каркасе.
- Словарь терминов — заглушка без терминов триллера; словари хуков расходятся (гайд, V11, R01,
  промпт карточек с пятью `hook_kind`, зашитыми в промпт).
- Термины героя заданы жанром, а не проектом; персоны триллера без медика/юриста.
- README/SPEC не соответствуют файлам.

### Поставщики и скрипты
- Резерв тарифицируется по максимальной цене (`providers/llm.ts:321-327`).
- `Number(arg)` без проверки: NaN отключает бюджет (`scripts/eval.ts:28`, `pilot.ts:11-12`).
- Нет `thinkingConfig` у Gemini; мысли входят в `maxOutputTokens`.
- Гонка бюджета при параллельных вызовах (перерасход до 4 вызовов).
- У Anthropic-потока нет таймаута на зависший поток.
- Smoke проверяет резерв с `maxOutput: 1000`, в бою до 65536.
- Кэш подсказок: текст блока не кэшируется; у Gemini кэша нет.
- Повтор при невалидном JSON не виден в прогрессе и пересылает весь плохой ответ.
- `critic_of_writer`/`helper` на 16000 токенов ответа без повтора при обрезании.
- Предупреждение `--localstorage-file` — из пакета `docx`, грузится в каждом скрипте.
- Цены `cache_read` для Opus/Fable нужно сверить; `.env` с BOM ломает первый ключ.

### Приложение
- Лимит 50 долларов нельзя поднять из приложения; ожидаемая цена сезона 130–280.
- Шаг нельзя остановить; «Сценарии» по умолчанию пишут все 60 серий.
- Ничего нельзь править руками: нет PUT/PATCH для библии, плана, карточек, фактов, хотя
  механика распространения правок (`memory/store.ts:265-294`) есть.
- Шаг «Сценарии» можно утвердить при 1 сценарии из 60.
- Переделка по находкам «слепая» для библии, плана, карточек.
- План сезона без частичного сохранения.
- «Это не дыра» требует указать факт.
- Параметры жанра (пэйволл, длина сезона, термины героя) не задаются проектом.
- Экспорт без пометки устаревших серий; нет PDF.
- `tsx watch` перезапускает сервер при любой правке файла и убивает оплачиваемый шаг;
  Vite не читает `.env` (порт сервера).

## План работ

Порядок задан тем, что даст наибольший прирост качества на рубль, и тем, что нужно до прогона по «Приме».

### Волна 0. Перед прогоном по «Приме» (без этого прогон бессмыслен)
1. Эталон с дырами: вариант `prima_v1` с 20–30 намеренными смысловыми дырами всех типов и
   `holes.yaml`; «Прима» остаётся чистой. Посев дыр расширить типами триллера.
2. Аудитор плана получает библию и таблицы (правила мира, ружья, улики, знание); цитаты из них
   засчитываются; строки серий получают тип обрыва, режим знания, настроение, якоря, `acts_on`.
3. Жанровая фильтрация: `genres` у категорий Ж/В и у принципов методик; вопросы каталога дыр
   переопределяются гайдом жанра; словарь по жанрам; убрать «мидпоинт/8-я/12 слов/три страдания»
   из общих текстов.
4. Тип дыры находки выбирается моделью из типов категории; eval сравнивает с полным списком.
5. Устойчивость: обрезанный или кривой ответ одного прохода не роняет прогон; повтор при
   обрезании; уровень размышлений Gemini в `models.yaml`; таймаут Anthropic; проверка чисел в
   аргументах скриптов; цена резерва; отчёт о цене при аварийном выходе.
6. Решение продюсера: рейтинг триллера 16+ или 18+.

### Волна 1. Полнота аудитора до 85%
7. Проходы по блокам каркаса плюс сквозной проход для категорий Е, Г, Д, О. Цена прогона
   вырастет примерно с 10 до 25–30 долларов.
8. Дедупликация по серии, фрагменту и вопросу; сопоставление с дырами продюсера окнами по 10
   серий с текстом плана; две цифры в отчёте: строгая и со спорными.
9. Отдельный проход «юрист/следователь/врач» по правовым и медицинским ходам.
10. Судья закрытия находок видит строки плана вокруг серии и требует серию, где факт показан.
11. Кодовые ложные срабатывания: агрегировать неотмеченные якоря, уточнить маркер насилия,
    понизить `*.unmarked` до minor, не цитировать события целиком.
12. Контролёры в eval, `locateQuote` в контролёрах, компактные вопросы «кто рядом» по блокам.

### Волна 2. Качество самого сериала
13. `runCodeChecks` для карточек и сценариев в приложении; находки в цикл `fix`.
14. План сезона: куски не меньше 10 серий, полная таблица предыдущих серий, шаг согласования
    по находкам кода, сохранение по частям.
15. Автор видит «что проверит критик»: правила категорий, `check.llm`, `fix_hints`, вопросы дыр.
16. Писатель: сжатие библии только при переполнении; поле «заложить» в карточке; контур плана и
    следующий хук; ведомость непрерывности из сценариев в факты.
17. Факты извлекать всегда и сливать; переделка библии/плана/карточек с открытыми находками;
    переписывание одной карточки вместо блока; `hook_type`/`hook_kind` как enum из каркаса.

### Волна 3. Приложение для продюсера
18. Лимит бюджета в проекте и кнопка «поднять»; остановка шага; выбор серий для сценариев;
    строка прогресса «серия 7 из 60, $X».
19. Правка руками: факты, события, карточка, сценарий; «Это не дыра» с причиной без факта.
20. Параметры жанра в проекте: пэйволл, длина сезона, термины героя (миграция БД).
21. Утверждение сценариев только при полном комплекте; пометка устаревших серий в экспорте;
    `pnpm dev` без перезапуска сервера на правку файлов; Vite читает `.env`.

### Волна 4. Порядок в данных
22. Общие правила в один файл; числа лимитов из одного источника; словарь терминов триллера;
    `hook_kinds` в каркас; параметрические номера в гайде и персонах; персона медика/юриста;
    README и SPEC по факту.

## Решения, которые нужны от продюсера
- Рейтинг вертикального триллера: 16+ или 18+.
- Бюджет одного прогона оценки после волны 1: около 25–30 долларов, допустимо ли.
- Лимит проекта по умолчанию для реального сезона (сейчас 50, оценка по ТЗ 130–280).
- Порядок волн: предлагаю 0 → 1 → 2 → 3 → 4; волны 2 и 3 можно переставить.
